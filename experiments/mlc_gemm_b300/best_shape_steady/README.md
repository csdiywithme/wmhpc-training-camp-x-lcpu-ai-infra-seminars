# 当前最高记录版本：最快已测形状与任务轮数

选择历史最高记录的 `hgemm_v9_wide`，保持实现不变：输入 pipeline 深度 3、
K tile 64、epilogue 128 列、两个 MMA consumer、双 CTA cluster。
历史最高吞吐为 `2048×9472×8192` 上的 1656.41 TFLOPS；这不表示 wide 在所有
形状上优于其他版本，也不证明它与 fenced 的微小差距有统计显著性。

该中心形状的旧清缓存性能实验已经完成，直接复用；新实验是 steady 协议下
`wide` 与 cuBLASLt 的同卡交错对照，并增加 K=8192 的两个未测邻近形状。

| M×N×K | 有效 cluster 输出 tile | 任务 | cluster worker | 逻辑轮数 | 槽位利用率模型 |
| --- | --- | ---: | ---: | ---: | ---: |
| 2048×9216×8192 | 512×256 | 144 | 74 | 2 | 97.30% |
| 2048×9472×8192 | 512×256 | 148 | 74 | 2 | 100.00% |
| 2048×9728×8192 | 512×256 | 152 | 74 | 3 | 68.47% |

基本 `BLK_M=128, BLK_N=128` 不是调度器分配的完整输出块：两个 CTA 和两个
consumer 合起来处理 512×256 输出。物理 grid 始终为 148 CTA，即 74 cluster。
任务数 `T=(M/512)*(N/256)`；每个 cluster 按步长 74 领取任务，最长工作序列
长度为 `ceil(T/74)`。K=8192 时每个任务有 128 个 K tile。

144 任务有 70 个 worker 做两块、4 个做一块；148 任务全部做两块；152 任务有
4 个 worker 做三块、70 个做两块。逻辑轮数不表示全局同步，也不是物理 grid
的 launch waves。槽位利用率只是等时任务模型，不能替代实测 SM/Tensor Core
利用率；实际性能还受缓存、流水线、写回及动态时钟影响。

## 新旧边界与库配置

- 三个形状的新测试均为连续复用缓冲区、不显式清缓存；不能把新结果与旧的
  清缓存结果作为改变内核后的受控加速比较。
- 中心形状 cuBLASLt 复用 `cublas_tuning/runs/20260920T045605Z` 已选出的
  算法配置，核对完整算法描述，不重复该形状的算法搜索。它不一定是稳态
  协议下的库全局最优配置。
- 两个新端点分别请求 32 个 Lt heuristic 候选，实际返回数量单独记录；
  每候选 seed0 完整验证，3×10 调优样本与正式 7 轮测量独立。
- FP16 输入/输出、FP32 累加、禁止 FP16 中间归约；相同三种子、完整输出
  校验、NaN 预填和计时后校验。两方同卡交错计时，保留原始样本和轮次来源。
- 不运行其他流水线版本、旧清缓存计时、NCU、CUDA Graph 或时钟/功率改动。

## 持久化

CPU-only 编译原生库和三个 wide 实例后才启动一次 B300；每个 case 完成后
提交 Modal Volume，逐轮原始数据原子落盘。禁止自动 GPU 重试。
使用 `--retrieve-only` 可以仅取回结果，不再次执行测量。
