# C1：C16 / C32 / C64 数值机制 GPU 实验

## 结论与实验边界

2026-09-13 在 NVIDIA B300 SXM6 AC 上运行了 6 个指数范围案例、45 个 Neumann 案例。结果支持三个结论：

1. `g=-5` 的原始指数分解在第 18 个 token 同时出现衰减因子归零和逆衰减因子溢出，因此不能直接把当前 C16 分解扩大到 C32 / C64。
2. C16 虽不发生上述范围溢出，FP16 Neumann 中间量仍可因抵消产生绝对误差 1。随机归一化 keys 的小误差不能替代对齐 keys 的压力测试。
3. 把同一 doubling 算法的中间矩阵全部改为 FP32，仍不足以可靠处理 C32 / C64 的最坏抵消；C64 的一个条件数仅 128 的例子得到约 `2.15e9` 的绝对误差。

这是独立的数值机制实验，不是修改 FlashKDA chunk 后的端到端实现。自定义 GEMM 使用与当前 K1 相同的 `mma.sync.aligned.m16n8k16.row.col.f16.f16.f16.f16` 指令类型，但矩阵及各阶段通过 global memory 传递；C32 / C64 使用多个 16×16 tile。实验直接构造 Neumann 输入 L，跳过输入 gate / beta 激活、BF16 keys 舍入及生成 L 的前级 GEMM。其误差不能直接替代完整 KDA 输出误差。

## Neumann 算法、参考值和阶段名

令 L 为严格下三角矩阵，`P2 = I-L`。每次 doubling 执行

\[
X\leftarrow X^2,\qquad P\leftarrow P+PX,
\]

其中初始 `X=L`。`power_4` 表示 L⁴，`partial_inverse_8` 表示已累计到七次幂的多项式

\[
P_8=I-L+L^2-\cdots-L^7.
\]

因此 C16 / C32 / C64 分别需要 6 / 8 / 10 次完整矩阵乘法，按 dense `2C³` 计数分别为 49,152 / 524,288 / 5,242,880 FLOPs。该计数没有利用三角稀疏性，也不是实际 fused K1 的指令成本。

所有模式接收同一份先舍入为 FP16 的 L。参考为 FP64 三角求解

\[
R_{\rm ref}=\operatorname{solve}_{\rm FP64}(I+L_{\rm FP16},I).
\]

因此报告的 `inverse_error` 主要度量逆算法本身的误差，`input_rounding` 单独报告构造 L 时的误差。参考也受 FP64 有限精度影响；例如极小的非零角点可能显示为零。对齐 keys 的解析公式提供额外独立核对。

三种模式为：显式 F16 MMA 累加 / 输出；Torch FP16 输入输出且请求禁用半精度 reduction / accumulation；全 FP32 且关闭 TF32。SASS 核对直接覆盖自定义扩展，不能据此声称每个 cuBLAS 路径具有相同的内部舍入次序。

## 对齐 keys：最终逆有界，但中间量巨大

对 `L=βJ`，其中 `J_ij=1` 当 `i>j`，精确结果为

\[
R_{ii}=1,\qquad R_{ij}=-\beta(1-\beta)^{i-j-1}\quad(i>j).
\]

当 β=1 时，R 只有主对角的 1 和第一下对角的 −1。对 C≥2，`||I+J||∞=C`、`||R||∞=2`，故 `κ∞(I+J)=2C`。然而

\[
(J^p)_{ij}=\binom{i-j-1}{p-1},
\]

使 doubling 中间量迅速增长，随后必须抵消。这是算法的数值稳定性问题，而不是声称本例线性系统本身具有天文量级条件数。

| C | β | 显式 F16 MMA 逆的最大绝对误差 | 相对 L2 误差 | 首个非有限阶段 |
|---:|---:|---:|---:|---|
| 16 | 1 | 0 | 0 | 无 |
| 16 | 0.990234375 | 1 | 0.196926 | 无 |
| 16 | 0.75 | 0.125000003 | 0.033232 | 无 |
| 32 | 1 | NaN | NaN | `partial_inverse_8` |
| 32 | 0.990234375 | NaN | NaN | `partial_inverse_8` |
| 32 | 0.75 | NaN | NaN | `power_8` |
| 64 | 1 / 0.990234375 / 0.75 | NaN | NaN | `partial_inverse_8` |

C16、β=1 的 L² / P₄ / L⁴ / P₈ / L⁸ 最大幅值分别为 `14 / 78 / 364 / 1716 / 3432`，此次硬件路径最终恰好抵消成精确逆。不能由这个特殊整数例推断邻近参数也准确：β=0.990234375 时，最左下角实测 −1，解析参考约 −`7.10458e-29`；逆残差最大值约 `0.742288`。β=0.75 时，实测角点 `0.125`，参考约 −`2.79397e-9`。这些异常在 Torch FP16 输出模式中也出现，所以扩大累加器而仍将阶段结果存为 FP16，不足以消除该问题。

C32、β=1 的 P₈ 精确最大幅值为 475,020，已经超过 FP16 范围。实测此阶段先出现 36 个 Inf；下一次乘法中的 `0×Inf` 可将 NaN 传播到原本为零的位置，最终 1024 个矩阵元素全部 NaN。C64 同例在 P₈ 出现 820 个 Inf，最终 4096 个元素全部 NaN。

使用 `L_ij=exp(-0.1(i-j))` 的衰减案例也暴露相同趋势：C16 半精度逆最大误差约 `0.250016`；C32 首次非有限在 L⁸，C64 在 P₈。由于该 L 已先舍入 FP16，这一行与 FP16 表示后矩阵的 FP64 逆比较，不将未舍入矩阵的解析双对角形式混作参考。

## 全 FP32 不是任意增大 chunk 的充分条件

| C | β | FP32 最大绝对误差 | FP32 相对 L2 误差 | 是否有限 |
|---:|---:|---:|---:|---|
| 16 | 0.990234375 | 0.0001220703 | 0.0000348732 | 是 |
| 32 | 1 | 8 | 1.00791 | 是 |
| 32 | 0.990234375 | 12 | 1.61193 | 是 |
| 32 | 0.75 | 0.03125 | 0.009609 | 是 |
| 64 | 1 | 2,147,483,648 | 600,348,758 | 是 |
| 64 | 0.990234375 | 120,259,084,288 | 1.17474e10 | 是 |
| 64 | 0.75 | 10,485,760 | 1.10519e6 | 是 |

例如 C64、β=1 的 FP32 P₃₂ / L³² 幅值约 `2.32714e17 / 4.65428e17`，最终所需结果幅值只有 1。避免指数溢出和保留有限数，并不能保证抵消后还保留正确有效位。因此需要分别评估指数分解、逆算法和状态存储；只修改其中一处精度不能构成完整稳定性保证。

作为分布对照，D=128 随机归一化 keys、β=0.7、gate=0 的三组半精度逆最大误差为 `5.28e-5 / 1.06e-4 / 1.00e-4`，全部有限；全 FP32 为 `8.37e-9 / 1.43e-8 / 2.87e-8`。这只覆盖固定种子的三个随机矩阵，不能提供所有归一化 keys 的最坏情况界。

## 指数因子、直接差分和居中

实验通过自定义 `ex2.approx.ftz.f32` 计算 `exp(G_i)` 与 `exp(-G_i)`，再转 BF16。G_i 为 FP32 构造的自然对数前缀和；内核乘 `log2(e)` 后执行 EX2。`k=1` 的恢复项按源代码的 BF16 乘积边界计算 `exp(-G_i) × BF16(exp(G_C))`。

| C | 每 token g | exp 归零 / 逆因子 Inf 首位置 | 原始恢复项 | 居中后两因子 |
|---:|---:|---|---|---|
| 16 | −5 | 均无 | 16 项有限 | 均有限 |
| 32 | −5 | 均为第 18 个 token | 17 个零、15 个 NaN | 均有限 |
| 64 | −5 | 均为第 18 个 token | 17 个零、47 个 NaN | 仍有零与 Inf |
| 16 / 32 / 64 | −0.01 | 均无 | 全部有限 | 均有限 |

第 18 个 token 对应 `G=-90`；该步已经跨过 FP32 normal 下界和上溢范围，符合 `FTZ` 机制。直接计算 `exp(G_C-G_i)` 在 C32 / C64 都没有 NaN，并且最后一个 token 的恢复因子为 1，但较远项仍会下溢：分别 14 / 46 个零。因此“直接差分避免 `0×Inf`”不等于“所有远距离项都精确保存”。

居中使用 `c=G_C/2`，仅检查 `exp(G_i-c)` 和其逆的表示范围。对包含 G₀=0 的区间，C32、g=−5 的半宽 80 尚可表示，C64 的半宽 160 则不行。本实验没有实现随之必需的状态、输出和跨 chunk 尺度补偿，不能称为完整 rescaled KDA；居中范围通过也不保证形成 L 时的抵消误差通过。

## 计时的使用限制

脚本保留了固定种子随机矩阵的 CUDA Graph 重放时间：显式 F16 MMA 路径 C16 / C32 / C64 中位数约 `12.36 / 22.63 / 39.01 μs`。每次重放包含生成单位阵、独立 GEMM、逐元素加法及 global intermediate；主机反复发起 graph replay 也可能造成空隙。这些数值仅便于复查本诊断程序的执行成本，不能用来估算寄存器内融合的 K1 耗时，不能据此断言 C32 / C64 完整 FlashKDA 的性能收益或损失。正式性能结论应引用单独的端到端基线、profile 和可运行候选。
