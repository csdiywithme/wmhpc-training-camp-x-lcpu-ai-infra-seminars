# 首轮假设与区分实验

以下是实验前的静态推导，不是 GPU 性能结果。以 D=128、C=16、GQA=16、page=128 为限。

## C1：融合究竟节省了什么

旧 K2 的两个状态投影、三角变换、输出修正、状态更新合计每 head/chunk 1,703,936 个浮点运算（一次乘加按两个 FLOPs）。三个新矩阵乘为：

| 阶段 | M,N,K | FLOPs |
|---|---|---:|
| 共享旧状态的两个投影 | 128,32,128 | 1,048,576 |
| U 的三角变换 | 128,16,16 | 65,536 |
| 共享 U 的输出修正与状态增量 | 128,144,16 | 589,824 |

总 FLOPs 没有减少。收益假设来自减少重复操作数准备、MMA 发射/完成等待，以及避免把逻辑 M=16 直接塞进较高的 tcgen05 M 维度。按每次 K16 发射统计，完全融合、拆分两头投影、拆分末段、全部拆分分别是 10、18、11、19 次；这只是静态发射数，不能直接推断周期数或速度比。

风险在于每个 chunk 的状态/操作数打包、TMEM 读取和 SMEM 标量处理。首版把 FP32 中间结果写入共享内存以便可靠检验，最大的 128×144 累加结果单独占 73,728 bytes；还有 BF16 状态、操作数与暂存。必须从编译结果取得真实 shared/register/spill，不能凭 GEMM 效率判断整条递推。

区分实验顺序：

1. 完整 forward 对原版与独立数学参考；先排除布局、递推和舍入错误。
2. fused / split-qk / split-final / split-both 在同卡同域比较；记录所用矩阵形状和完整成本。若融合反而更慢，检查宽结果消费与资源占用。
3. 对确认占主导的中间存储做消融：直接按 TMEM 分区消费结果、缩短活跃区、避免整块 FP32 shared 暂存。保持各 BF16 舍入位置和初态语义。
4. 对短任务与长链分别看 CTA 数量、状态串行依赖与供数；只有数据支持时才尝试 value 切分或下一 chunk 预取。切分必须真正减少每 CTA 的状态和传输资源。

## C2：转置把成本搬到了哪里

每个 head-group/page 的 QK 与 PV 共 1,048,576 FLOPs。BF16 K/V 有效元素共 65,536 bytes，忽略 Q、workspace、页表及其他流量时只是 16 FLOPs/byte 的算术强度估计。不能据此直接套用整个 GPU 峰值带宽；实际页共享、cache、CTA 数量和不连续加载均有影响。

转置的两次 MMA 都是 M128,N16,K128。QK 输出的 token 维度变成 M，softmax 需要跨线程归约；PV 的 V^T 又可能使普通 global load 的连续性变差。首版用同一个 A shared 缓冲、显式 warp 归约与共享中间结果，目的是先检验完整分页语义。

区分实验顺序：

1. 冻结 full gate 验证分页、causal、scale、padding 和 metamorphic 输入；记录每个 case 实际 backend。
2. 同一输入比较原 partial+原 merge、原 partial+旧优化 merge、新 partial+同一个 merge。这样才能区分 partial 收益与早已存在的 merge 收益。
3. 固定数学路径与 split，比较普通加载与 TMA 供数；PV 可探索 Major::MN 映射，以连续维度搬入 V 后直接作为 V^T 使用。描述符、共享布局和地址对齐需要实测验证。
4. 分别扫描 1/4/16 splits 等配置，区分 CTA 并行度和单 CTA 页间流水。每 CTA 一页时没有下一页可预取，多 stage 不会自动创造收益。
5. 若 TMEM→softmax→SMEM 成为主项，对照 query-major 布局或混合指令实现；原生 FP8 额外量化 Q/P 是另一条精度路线，不能与 FP8 存储兼容混为一谈。

## 停止与继续的证据

编译失败先保留完整错误与源快照；数值失败先缩小触发输入，再谈速度。正确但慢的首版是有效的设计反馈，下一轮应由资源、时间线或单变量对照选择。任何局部胜出都须回到完整 C1 forward / C2 attention chain 验证。最终目标是给出可复现的改进或有解释力的负结果，不以有限搜索声称全局最优。
