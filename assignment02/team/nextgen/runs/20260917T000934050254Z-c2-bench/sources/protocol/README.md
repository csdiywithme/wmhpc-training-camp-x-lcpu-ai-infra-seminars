# C1 / C2 新指令后端探索

开始日期：2026-09-16。此目录记录在现有团队题之后开展的新一轮实验；旧报告与结果保持原样。

用户目标：实际探索 C1 / C2 在新指令集上的性能，允许使用其 Modal B200/B300，并详细记录思路、实验步骤、过程与结论。后续明确优先使用 `simidawhu` Modal profile。

## 研究范围与完成依据

本轮同时推进两条路线，不能以单 tile / 单页微基准代替完整算子交付：

- C1：保留 C16 与上游 K1 的数值算法，实现完整多 chunk tcgen05 K2，比较共享操作数计算的合并与拆分；在真实 forward 中核对输出和状态，覆盖短序列、长序列、varlen 与状态接口，并以同卡基线测量。对失败和无收益方案保留记录。
- C2：实现分页 tcgen05 attention 的完整 partial 路径，与 merge 组成完整算子链；验证 top-k、页表、causal 尾页、空 split 和 scale 语义。先建立 BF16 路径，再评估 FP8 存储兼容、数据布局、供数与调度；沿用已有冻结数值验收，测量同卡完整链。
- 根据真实数据决定后续 TMA、流水、资源分片或混合指令路径。若具体方案失败，定位可检验的原因并至少验证有根据的后续改动；不能用孤立 MMA 变快推导整体收益。
- 最终交付包括源码、环境与源码哈希、命令和退出码、原始输出、正确性覆盖、性能样本、实验过程、负结果与结论。声明未验证的架构、输入域和服务级收益，不承诺全局最优。

具体准入见 `ACCEPTANCE.md`；逐次记录见 `JOURNAL.md`。

## 目录与职责

- `../c1_flashkda/nextgen/`：独立 C1 候选、构建、测试和设计记录。
- `../c2_msa_decode/nextgen/`：独立 C2 候选、构建、测试和设计记录。
- `prepare_run.py`：冻结一次运行需要的源码与元数据，避免运行中源码变化影响追溯。
- `modal_runner.py`：显式账户、限时 CPU 构建与单 GPU 实验，保存构建和运行失败。
- `runs/`：每次提交的不可覆盖快照与返回产物。

## 实验纪律

1. 默认使用 B300；B200 在构建目标匹配且有比较意义时使用。每次实际设备型号由远程输出记录。
2. 每个远程函数设硬超时、零自动重试、单容器上限。CPU 预编译通过后才启动 GPU 阶段。
3. 所有提交显式设置 `MODAL_PROFILE=simidawhu`。不改账户全局默认，不记录凭据。
4. 保存必要源码的冻结快照。上游、现有用户练习、旧报告均不覆盖。
5. 正确性失败不得进入正式性能汇总；诊断计时必须明确标记不可用于速度结论。
6. 普通 CUDA Graph 计时与 profiler 重放分开；同卡交错比较，公开所有已测配置和退化。
7. 调参样本与最终验证样本分离；不得依据候选误差放宽冻结门槛。

## 当前状态

已使用 `simidawhu` 的真实 B300 完成首版完整正确性、完整链benchmark与NCU。首版均正确但显著变慢；C1直接消费TMEM的两种第二版也完成全域验收与性能测量，改善有限。C2在做连续供数/padding消融，C1在做release/宽TMEM读取消融。最新实测见 `RESULTS.md`，原始失败与决策见 `JOURNAL.md`。所有结论限制在已测域，不称全局最优。

## 运行方式

先运行 `python prepare_run.py --track c2 --mode smoke`，记录输出的绝对 run 目录。之后用 `MODAL_PROFILE=simidawhu MODAL_DISABLE_API_PROXY=1 NEXTGEN_RUN_DIR=<run目录> uv run --python 3.11 --with modal==1.5.5 python -m modal run <run目录>/sources/protocol/modal_runner.py`。本轮本地与镜像统一使用 Python3.11；远端通过冻结模块导入函数，本机路径只在 local guard 内读取。实际运行冻结目录中的 runner，不使用运行中可能修改的工作副本。

C1 使用 `--track c1 --variant fused`；融合/拆分及后续变体分别产生快照。首版只提供 B300 基线镜像，B200 需要重新构建匹配的基线，不能把 sm_103a 二进制直接用于 B200。当前支持 smoke、verify、bench、profile 四种模式；profile使用不锁频的NCU，不能与常规计时混合。

同一候选通过编译后，下一阶段可加 `--reuse-build-from <旧run目录>`。准备器会验证架构、编译参数、编译源哈希及二进制包哈希；只改 Python 测试入口时可复用，修改 CUDA/C++ 源码后必须重新编译。已有 state 的运行不得重启，应先检查原调用句柄和终止状态。
