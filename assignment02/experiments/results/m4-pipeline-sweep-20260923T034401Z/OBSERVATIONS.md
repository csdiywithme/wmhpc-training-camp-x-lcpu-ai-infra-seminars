# 4.3 stage 扫描：B300，2026-09-23

NVIDIA B300 SXM6 AC，CUDA 13.1，`sm_100f`。将同一份源码以 `STAGES=2/3/4/6` 分别强制重编，两个指定形状共八个组合全部按程序的逐元素数值比较 PASS（`bad=0`）。每条运行命令 `timeout -k 2s 5s`，没有超时或自动重试。上传源码快照的 SHA256 与远端返回值一致；完整命令及输出见 [`run.json`](run.json)。

| M × N × K | S=2 | S=3 | S=4 | S=6 |
|---|---:|---:|---:|---:|
| 4096³，TFLOPS | 512.7 | 476.0 | 397.1 | 239.5 |
| 256 × 4096 × 16384，TFLOPS | 220.6 | 226.7 | 229.6 | 229.3 |

每份 stage 的 A/B 需 `(128+64)×64×2 = 24 KiB` shared memory；kernel 另申请 1 KiB 以满足 1024 字节对齐。因此动态 shared memory 分别为 49、73、97、145 KiB/CTA。按 S=3 的 NCU 报告所示约 228 KiB/SM 的 shared memory 配置、每 CTA 约 1 KiB 驱动开销及少量静态 shared memory 计算，shared-memory 限制下的理论常驻 block 数依次为 **4、3、2、1**。这组数字是资源计算；只有 S=3 的 3 block/SM 经过 NCU 直接验证。

4096³ 的 grid 为 `32×64=2048` blocks。stage 增多使可同时驻留的 block 数减少、总波次数增加；当前实现中更深预取的收益没有抵消这项并发损失。第二形状的 grid 为 `2×64=128` blocks，小于 B300 的 148 SM：即使 S=6 每 SM 只可驻留一块，这个 grid 本来就无法让每 SM 同时跑多块。它的 K 维有 256 轮，较深预取能稍微减少单块的等待，S=2→4 提升约 4.1%，S=4→6 没有明显增益。

以上是单次、未锁频的普通运行；小幅差异需重复测量才能断定显著性。完整的 S=3 [`NCU 报告和源码热点分析`](../m4-pipeline-ncu-20260923T033628Z/OBSERVATIONS.md)另存。这里的结果说明所有指定组合通过了本次检查，不等于稳态时空图、梯子表的 naive 行以及 4.3 三问均已完成。
